# Domain docs

## Before exploring

Use the single-context layout:

- Read `GLOSSARY.md` at the repository root.
- Read relevant architecture decision records in `docs/adr/`.

If these files are absent, proceed silently. Domain-modeling creates
them when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms when naming concepts in issues, proposals,
hypotheses, and tests.

If a needed concept is missing, reconsider whether it belongs to the
project or note the gap for domain-modeling.

## Decisions

Surface contradictions with existing ADRs explicitly. Identify the
ADR and explain why the decision may need reopening.
